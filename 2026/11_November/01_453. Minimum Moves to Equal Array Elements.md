**Problem Name:** Minimum Moves to Equal Array Elements
**Difficulty:** Medium
**Tags:** `Array`, `Math`

## 📖 Problem Statement

Given an integer array `nums` of size `n`, return the minimum number of moves required to make all array elements equal.

In one move, you can increment `n - 1` elements of the array by `1`.

---

## ⚠️ Constraints

- `n == nums.length`
- `1 <= nums.length <= 10^5`
- `-10^9 <= nums[i] <= 10^9`
- The answer is guaranteed to fit in a 32-bit integer.

---

## 💡 Examples

| Example | Input | Output | Explanation |
| :--- | :--- | :--- | :--- |

| **2** | `nums = [1,1,1]` | `0` | All elements are already equal. |

## 🧠 Explanation & Approach

### The Core Idea (Translating the problem)
The problem asks us to increment $n - 1$ elements by $1$ in each move until all elements are equal. 

If we simulate this directly (Brute Force), a greedy approach would be to always find the maximum element and increment all *other* elements. However, since the constraints on $n$ are up to $10^5$, an $O(n^2)$ simulation will result in a Time Limit Exceeded (TLE) error.

### The Mathematical Insight
Let's change our perspective. Incrementing $n - 1$ elements by $1$ is mathematically equivalent to **decrementing exactly $1$ element by $1$** relative to the rest of the array. 

Our ultimate goal is to make the gap between the maximum and minimum elements $0$. Instead of pushing all smaller elements up to the maximum, we can simply pull the larger elements down to the minimum element.

For any element `nums[i]`, the number of moves required to reduce it to the `min_element` is `nums[i] - min_element`. 
Therefore, the total number of moves for the entire array is the sum of these individual moves:
`Total Moves = Σ (nums[i] - min_element)`

Which simplifies algebraically to:
`Total Moves = (nums[0] + nums[1] + ... + nums[n-1]) - (n * min_element)`
`Total Moves = Sum(nums) - n * min_element`

## 💻 Solution Code

### Brute Force Solution
```cpp
// Intuition: Incrementing n-1 elements is equivalent to skipping the max element each time. We can simulate this to bring all elements closer together.
// Approach: Find the maximum element in the array. Increment all other elements by 1. Repeat this process until all elements in the array are equal.
// Time Complexity: O(n^2) because for each move we iterate through the array to check equality and find the max element.
// Space Complexity: O(1) as we are modifying the array in place with a few extra variables.
class Solution {
public:
    bool allEqual(vector<int>& nums) {
        // Check if all elements match the first element
        for (int i = 1; i < nums.size(); i++) {
            if (nums[i] != nums[0]) return false;
        }
        return true;
    }

    int minMoves(vector<int>& nums) {
        int n = nums.size();
        int moves = 0;

        while (!allEqual(nums)) {
            // Find the max element's index
            int maxIdx = 0;
            for (int i = 1; i < n; i++) {
                if (nums[i] > nums[maxIdx]) maxIdx = i; // Track the largest element
            }

            // Increment everything except the max
            for (int i = 0; i < n; i++) {
                if (i != maxIdx) nums[i]++;
            }
            moves++; // Increment move count
        }

        return moves;
    }
};

/*
*
* Dry Run
* Input: nums = [1,2,3]
* Step 1: max=3 (idx=2). Increment others: [2,3,3], moves=1
* Step 2: max=3 (idx=1). Increment others: [3,3,4], moves=2
* Step 3: max=4 (idx=2). Increment others: [4,4,4], moves=3
* Array is equal. Return 3.
*
*/
```

### Optimized Solution (Two Pass)
```cpp
// Intuition: Incrementing n-1 elements by 1 is mathematically the same as decrementing 1 element by 1. We just need to reduce every element down to the minimum element.
// Approach: Find the total sum of the array and the minimum element. The total moves required is the total sum minus (n * minimum element).
// Time Complexity: O(n) because we iterate through the array twice (once for sum, once for min).
// Space Complexity: O(1) as we only store a few integer variables.
class Solution {
public:
    int minMoves(vector<int>& nums) {
        int n = nums.size();
  
        // Calculate total sum of array
        int sum    = accumulate(begin(nums), end(nums), 0);
        // Find the absolute minimum element
        int min_el = *min_element(begin(nums), end(nums));

        // Apply mathematical formula
        return sum - n*min_el;
    }
};

/*
*
* Dry Run
* Input: nums = [1,2,3], n = 3
* sum = 1 + 2 + 3 = 6
* min_el = 1
* return 6 - (3 * 1) = 3
*
*/
```

### Optimal Solution (One Pass)
```cpp
// Intuition: We can optimize the two-pass mathematical approach into a single pass to save a bit of overhead.
// Approach: Iterate through the array exactly once, simultaneously accumulating the sum and tracking the minimum element. Then return the mathematical formula result.
// Time Complexity: O(n) as we traverse the array in a single pass.
// Space Complexity: O(1) as we only maintain the sum and min variables.
class Solution {
public:
    int minMoves(vector<int>& nums) {
        int n = nums.size();
  
        int sum    = 0;
        int min_el = INT_MAX;

        // Traverse once to find both sum and min
        for(int i = 0; i < n; i++) {
            sum += nums[i]; // Accumulate array sum
            min_el = min(min_el, nums[i]); // Update minimum element seen so far
        }

        // Apply mathematical formula
        return sum - n*min_el;
    }
};

/*
*
* Dry Run
* Input: nums = [1,2,3], n = 3
* Init: sum = 0, min_el = INT_MAX
* i=0: sum = 1, min_el = 1
* i=1: sum = 3, min_el = 1
* i=2: sum = 6, min_el = 1
* return 6 - (3 * 1) = 3
*
*/
```

## 📌 Notes & Key Insights
- **Relative Moves:** Recognizing that incrementing $n-1$ elements is a relative shift. Shifting $n-1$ items up by $1$ shrinks the gap to the highest element by $1$, exactly the same as shifting $1$ item down by $1$.
- **Data Types Warning:** While constraints guarantee the final answer fits in a 32-bit integer, calculating the `sum` might overflow standard integers if the array size and values are pushed to absolute max limits. In LeetCode's environment for this specific problem, `int` passes, but using `long long` for `sum` in production is safer.
